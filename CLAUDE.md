# avrora_bot — инструкции для Claude

VK-бот волейбольного клуба «Аврора». Проект в проде с 2026-09-23.

## Документы проекта

- `Техническое задание на разработку.md` — требования (ТЗ). Источник истины
  для проверки.
- `PLAN.md` — бэклог: все задачи ТЗ и новые, со статусами и карточками.
- `MEMORY.md` — факт: что сделано, решения, отклонения от ТЗ, окружение.
  Прочитай его в начале работы над задачей.
- `HARNESS.md` — как устроен агентский цикл разработки.

## Как работаем

- Задачи ведутся агентским циклом `/dev-loop <T-id>`: implementer пишет код,
  spec-reviewer независимо проверяет на соответствие ТЗ (см. `HARNESS.md`).
- Код пишется только по задаче со статусом `ready` в `PLAN.md`; план сначала
  согласуется с заказчиком.
- **Если заказчик пишет требование или задачу, которых нет ни в ТЗ, ни в
  `PLAN.md`, — сразу занеси: задачу — в `PLAN.md`, требование к продукту —
  ещё и в ТЗ (подними версию ТЗ).**
- По завершении задачи факт фиксируется в `MEMORY.md`, статус — в `PLAN.md`.
- Коммиты делает заказчик. Агентам — никаких git-команд, меняющих рабочее
  дерево или историю (`commit`, `stash`, `checkout`, `reset`, `clean`, `rebase`).

## Правила кода

- Слои: `domain` (сущности, порты, чистые сервисы) → `application` (use
  case'ы) → `adapters` (БД, VK). Новый раздел бота — по образцу ближайшего
  существующего.
- Права проверяются в use case'е на момент действия (ТЗ 5.2).
- Изменения схемы — только новая ревизия Alembic поверх head; миграции не
  импортируют код проекта; применённые ревизии не трогать.
- ПД (ФИО, телефон, дата рождения) — не в `action_log.details` и не в логах.
- Тексты бота — по-русски. Стиль — ruff (строка 80, одинарные кавычки).
- Проверка: `scripts/check.sh` (полный прогон тестов на WSL-маунте — 2–4 мин;
  для итераций — `scripts/check.sh tests/test_<файл>.py`).
