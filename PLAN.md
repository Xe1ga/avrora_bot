# PLAN — план работ avrora_bot

Единый бэклог проекта. Источник требований — `Техническое задание на разработку.md`
(далее ТЗ); факт выполнения, решения и отклонения — `MEMORY.md`; как работает
агентский цикл — `HARNESS.md`.

**Правила ведения**

- Каждая задача имеет id `T-<этап>.<номер>` (этапы ТЗ 1–4), `T-NF.<n>` —
  нефункциональные требования и безопасность, `T-X.<n>` — задачи вне ТЗ.
- Новое требование, которого нет ни в ТЗ, ни здесь, сразу заносится: задача —
  в этот файл, требование к продукту — ещё и в ТЗ (с поднятием версии ТЗ).
- Статусы: `backlog` → `planning` (идёт проработка, вопросы заказчику) →
  `ready` (план согласован, можно писать код) → `in-progress` → `review`
  (проверка на соответствие ТЗ) → `done` (принято, ждёт/получило коммит).
  Дополнительно: `partial` (сделано частично, остаток описан в карточке),
  `blocked`, `deferred` (вне текущего периметра).
- Код по задаче пишется только из статуса `ready`. Перевод в `ready` — только
  после явного согласия заказчика.
- Коммиты делает заказчик сам; агенты не коммитят.

### T-2.3 Голоса за абонемент из опроса VK
- **Статус:** planning — ждём `VK_USER_TOKEN` от заказчика (2026-10-04)
- **ТЗ:** 3.2 п.1 (дополнительный сценарий), глоссарий (`vk_poll`)
- **Запрос заказчика:** в сообществе есть опрос, например «Абонемент
  октябрь», варианты «Сдам абонемент» и «Буду разово». Ключевое слово
  «абонемент» в варианте — голос ЗА абонемент, «разово» — будет платить
  разово. Взять vk_id проголосовавших ЗА абонемент и автоматически добавить
  их в список голосов месяца (как «добавить голос <период> <vk_id>»).
- **Ограничение VK API:** список проголосовавших отдаёт `polls.getVoters`
  (в ТЗ ошибочно `polls.getVotes`). Анонимный опрос голосующих не раскрывает.
- **Проверено 2026-10-02 токеном сообщества бота** (по решению заказчика —
  сначала пробовать его): `wall.get`, `polls.getVoters`, `polls.getById` —
  все отвечают `ERROR 27: Group authorization failed: method is unavailable
  with group auth`. Токеном сообщества задачу не решить: нужен ключ
  пользователя (`VK_USER_TOKEN`), решение — за заказчиком.
- **Проверено 2026-10-02 сервисным ключом приложения** (по решению
  заказчика): `wall.get` работает, но `polls.getById` и `polls.getVoters` —
  `ERROR 28: Application authorization failed: method is unavailable with
  service token`. Остаётся только ключ пользователя.
- **Решения (заказчик, 2026-10-02):**
  - Опрос сборщик/админ присылает боту сам (пересылает пост/опрос в чат с
    ботом); автопоиска на стене нет.
  - Перед записью — сводка с кнопкой «✅ Добавить».
  - Голосовавшие «разово» ни на что не влияют (максимум — число в сводке).
  - Доступ: сборщик и администратор.
  - Токен: ключ пользователя `VK_USER_TOKEN` (решение заказчика 2026-10-02;
    ключ сообщества и сервисный ключ не подходят, см. выше). Используется
    только для `polls.getVoters`, в логи не пишется, хранится в `.env`.
- **Получение `VK_USER_TOKEN` (делает заказчик; токен в чат не присылать):**
  1. Аккаунт: лучше отдельный служебный, участник сообщества «Аврора» (и
     беседы, если опрос в беседе) — токен действует от его имени и должен
     видеть опрос.
  2. ID приложения: dev.vk.com → «Мои приложения» → приложение (то, чей
     сервисный ключ в `vk_mcp`, или новое типа Standalone) → «ID
     приложения»; приложение должно быть включено.
  3. (Устарело 2026-10-05: работает только у старых Standalone-приложений,
     см. ниже.) Под выбранным аккаунтом открыть (подставить ID):
     `https://oauth.vk.com/authorize?client_id=<ID>&display=page&redirect_uri=https://oauth.vk.com/blank.html&scope=offline&response_type=token&v=5.199`
     → «Разрешить» → в адресной строке
     `…blank.html#access_token=<ТОКЕН>&expires_in=0&user_id=…`;
     токен — между `access_token=` и `&`; `expires_in=0` — бессрочный
     (право `offline`).
  4. Записать в `avrora_bot/.env`: `VK_USER_TOKEN=<ТОКЕН>` (`.env` в
     `.gitignore`) и сообщить «готово» + ссылку на пост с тестовым опросом.
  - Если VK пишет, что приложение не поддерживает такой способ авторизации,
    или `access_token` не выдан — приложение новой схемы VK ID (ключ ~1 час +
    refresh-ключ): объём задачи растёт (хранение и обновление ключа), решить
    с заказчиком.
  - Если проверка даст «нет доступа» (ошибка 15) — получить токен заново с
    `scope=offline,wall`.
  - Отзыв токена: VK под этим аккаунтом → «Настройки → Приложения» →
    удалить приложение.
- **2026-10-05:** ссылка `oauth.vk.com/authorize` (Implicit Flow) вернула
  `{"error":"invalid_request","error_description":"application was deleted"}`.
  По dev.vk.ru («Ключ доступа пользователя»): для сайтов и сервисов ключ
  пользователя выдаётся **только через сервис авторизации VK ID**, срок
  действия — **1 час** (дальше — обновление refresh-ключом). Implicit Flow с
  `offline` (бессрочный ключ) остался лишь у старых Standalone-приложений,
  которым права выдавались раньше. `polls.getVoters` принимает любой ключ
  пользователя, особые права не нужны (базовых прав VK ID должно хватить).
  Значит, в объём задачи, скорее всего, войдёт хранение refresh-ключа и
  `device_id` (в БД: refresh-ключ при обновлении заменяется новым),
  автообновление ключа доступа и уведомление админа при сбое обновления.
  Точную схему (без SDK, Web) уточнить по документации id.vk.com
  (из песочницы закрыт сетевой политикой).
- **Следующие шаги:** заказчик получает токен → оркестратор проверяет его
  (`polls.getVoters` на тестовом опросе, только чтение) → критерии приёмки
  в карточку → согласование → статус `ready` → `/dev-loop T-2.3`.
- **Критерии приёмки:** — (после согласования)
